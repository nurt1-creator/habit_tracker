## Запуск проекта

```bash
uv sync
uv run -m app.main
```

Запуск обязательно из корня проекта (`habit_tracker/`), не из папки `app/`.
Причина — см. [про `-m` и поиск модулей](#импорты-и-запуск-как-модуля).

## Архитектура

```
habit_tracker/
├── app/
│   ├── __init__.py
│   ├── enums.py         # HabitStatus, HabitFrequency
│   ├── exceptions.py    # HabitArchivedError, DuplicateLogError, DuplicateHabitError
│   ├── models.py         # Habit, HabitLog
│   ├── repository.py     # HabitLogRepository
│   ├── user.py            # User
│   └── main.py            # точка входа
├── README.md
├── DOCS.md
└── .gitignore
```

Слои ответственности:

| Слой | Отвечает за |
|---|---|
| `models.py` | Сущности предметной области и их внутренние правила валидации |
| `repository.py` | Хранение коллекции `HabitLog` и операции над ней (поиск, статистика) |
| `user.py` | Владение привычками, уникальность названий в рамках пользователя |
| `enums.py` | Фиксированные наборы допустимых значений |
| `exceptions.py` | Доменные ошибки — сигнализируют о нарушении бизнес-правил |

`Habit` намеренно **не знает** о своём владельце (`User`) — односторонняя связь
`User → Habit`. Подробнее см. [Циклические зависимости](#циклические-зависимости).

## Модуль enums

### `HabitStatus`

| Значение | Смысл |
|---|---|
| `ACTIVE` | Привычка активна, можно отмечать выполнение |
| `ARCHIVED` | Привычка в архиве, отметки запрещены |

### `HabitFrequency`

| Значение | Смысл |
|---|---|
| `EVERYDAY` | Ежедневная привычка |
| `EVERYWEEK` | Еженедельная привычка |

## Модуль exceptions

| Исключение | Выбрасывается, когда |
|---|---|
| `HabitArchivedError` | Попытка создать `HabitLog` для архивной привычки |
| `DuplicateLogError` | Попытка отметить одну привычку дважды за одну дату |
| `DuplicateHabitError` | Попытка добавить пользователю привычку с уже занятым названием |

Использование доменных исключений вместо `ValueError`/`Exception` везде, где
ошибка отражает **нарушение бизнес-правила**, а не техническую проблему —
позволяет отдельно ловить и обрабатывать такие случаи в вызывающем коде.

## Класс `Habit`

Представляет привычку пользователя.

### Поля

| Поле | Тип | Доступ | Правило |
|---|---|---|---|
| `name` | `str` | read/write через property | Не может быть пустым или из пробелов; пробелы по краям обрезаются |
| `description` | `str` | read/write через property | Пробелы по краям обрезаются |
| `frequency` | `HabitFrequency` | read/write через property | Должен быть валидным `HabitFrequency` (проверка `isinstance`) |
| `status` | `HabitStatus` | read-only property | Меняется только через `archive()` / `activate()` |
| `created_at` | `date` | read-only property | Выставляется автоматически при создании, неизменяем |

### Методы

- **`archive() -> None`** — переводит привычку в статус `ARCHIVED`
- **`activate() -> None`** — переводит привычку в статус `ACTIVE`

### Пример

```python
habit = Habit("Brainstorm", "Study 2 hours everyday", HabitFrequency.EVERYDAY)
habit.archive()
print(habit.status)  # HabitStatus.ARCHIVED
```

## Класс `HabitLog`

Факт выполнения привычки в конкретную дату. Связан с `Habit` через композицию
(хранит прямую ссылку на объект).

### Поля

| Поле | Тип | Правило |
|---|---|---|
| `habit` | `Habit` | Привычка должна быть активна на момент создания лога |
| `completed_date` | `date` | Не может быть датой в будущем |

### Валидация при создании

```python
HabitLog(habit, date.today() + timedelta(days=1))
# ValueError: Completed date can not be in future

habit.archive()
HabitLog(habit, date.today())
# HabitArchivedError: Habit archived
```

Проверка "нельзя дважды за один день" **не входит** в `HabitLog` — она
требует сравнения с другими логами и реализована в `HabitLogRepository`.

## Класс `HabitLogRepository`

Хранилище всех `HabitLog` и логика анализа истории выполнения.

### Методы

#### `add(log: HabitLog) -> None`

Добавляет лог. Выбрасывает `DuplicateLogError`, если для той же привычки
уже есть лог на ту же дату.

#### `get_logs_for_habit(habit: Habit) -> list[HabitLog]`

Возвращает все логи конкретной привычки.

#### `get_current_streak(habit: Habit) -> int`

Количество дней подряд **до сегодня включительно**. Идёт от сегодняшней
даты назад, пока дата присутствует среди отметок.

```
Отметки: 28, 29, 30 сентября (сегодня)
current_streak = 3
```

#### `get_longest_streak(habit: Habit) -> int`

Самая длинная серия подряд идущих дат за всю историю, независимо от того,
когда она была.

```
Отметки: 25, 26, 28, 29, 30 сентября
longest_streak = 3  (28-29-30, серия 25-26 короче)
```

Алгоритм: сортировка дат → проход по соседним парам → сброс счётчика при
разрыве больше 1 дня → **обязательное** финальное сравнение после цикла
(иначе теряется серия, заканчивающаяся последним элементом списка).

## Класс `User`

Владелец набора привычек.

### Поля

| Поле | Тип | Правило |
|---|---|---|
| `name` | `str` | Не может быть пустым |
| `_habits` | `list[Habit]` | Уникальность по `name` в рамках пользователя |

### Методы

#### `add_habit(habit: Habit) -> None`

Добавляет привычку. Выбрасывает `DuplicateHabitError`, если у пользователя
уже есть привычка с таким же названием.

#### `get_habit_by_name(name: str) -> Habit | None`

Ищет привычку по названию. Возвращает `None`, если не найдена (не
исключение — отсутствие результата здесь не ошибка, а нормальный исход).

#### `get_completion_rate(habit: Habit, days: int = 30) -> float`

Процент выполнения привычки за последние `days` дней (включая сегодня).

Ожидаемое количество выполнений зависит от `frequency`:
- `EVERYDAY` → ожидается `days` выполнений
- `EVERYWEEK` → ожидается `days / 7` выполнений

```
habit (EVERYWEEK), 1 отметка за последние 30 дней
ожидаемое = 30 / 7 ≈ 4.29
completion_rate = 1 / 4.29 × 100 ≈ 23.3%
```

Результат не ограничен сверху — если отметок больше, чем ожидалось,
процент может превышать 100%, показывается как есть.

## Справочник концепций

Коротко — что применено в коде и зачем, для быстрого вспоминания.

### `@property` / `@setter`

Позволяет обращаться к методу как к обычному атрибуту (`habit.name`, без
скобок), но с возможностью валидации при чтении/записи. Property без
`setter` — атрибут только для чтения.

### Property vs метод-действие

Property — для **значений** (`status`, `name`). Действия, которые меняют
состояние (`archive()`, `activate()`), должны быть обычными методами со
скобками — так по вызову видно, что это команда, а не чтение поля.

### `Enum`

Фиксированный набор допустимых значений вместо "голых" строк — защита от
опечаток и связывание всех допустимых вариантов в одном месте.

Аннотация типа (`val: HabitFrequency`) не проверяется Python в рантайме —
для реальной защиты в `setter` нужен `isinstance(val, HabitFrequency)`.

### `ValueError` vs `TypeError`

`ValueError` — значение подходящего типа, но некорректно по смыслу (пустая
строка). `TypeError` — значение неподходящего типа вообще (не `Enum`, когда
ожидался `Enum`).

### Сравнение объектов по полю, а не по `is`

`is` сравнивает идентичность объекта в памяти — ненадёжно, если объекты
могут загружаться заново (например, из БД). Сравнение по смысловому полю
(`habit_a.name == habit_b.name`) не зависит от того, один ли это объект
в памяти.

### Циклические зависимости

`Habit` не хранит ссылку на `User`, хотя `User` хранит список `Habit`.
Причина: `Habit` не нуждается в знании о владельце для своей работы —
владение это ответственность `User` (принцип единственной ответственности).
Двусторонняя связь усложнила бы создание объектов и сериализацию без
реальной необходимости.

### Импорты и запуск как модуля

`uv run app/main.py` запускает файл напрямую — Python ищет модули от папки
файла (`app/`), поэтому `from app.models import ...` не находит пакет `app`.

`uv run -m app.main` запускает как модуль пакета — поиск ведётся от корня
проекта, импорты с полным путём (`app.models`) работают корректно.

### `set` vs `list` для проверки `in`

`in` для `list` — O(n), перебор элементов по очереди. `in` для `set` —
O(1) в среднем, за счёт хеширования значения и прямого перехода к ячейке.
Используется в `get_current_streak` для быстрой проверки "есть ли дата
среди отметок".
